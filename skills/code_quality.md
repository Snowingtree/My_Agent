# 代码质量检查

这个技能用于提高 Agent 写代码和改代码的质量。它不是替代 `coding_agent`，而是在编码任务中补充质量检查标准。

## 使用时机

- 用户要求创建、修改、修复、重构代码。
- 任务影响多个文件、公共函数、接口、配置或构建流程。
- 代码已经写完，需要检查是否可靠。
- 验证命令失败，需要根据错误定位并修复。

## 修改前要求

1. 先读取项目上下文，不要直接写文件。
2. 至少使用一次 `list_files`、`search_text` 或 `read_file`。
3. 明确相关文件、入口、已有工具函数、现有命名和代码风格。
4. 如果目标文件已存在，修改前必须先读取它。
5. 不要为了快速通过而删除已有逻辑、跳过错误或绕开验证。

## 修改时要求

- 优先做小范围、可解释的修改。
- 优先复用项目已有模式，不随意引入新依赖。
- 保持函数边界清晰，避免把无关逻辑混在一起。
- 对外部输入、空值、异常路径和权限边界做基本处理。
- 不要修改与任务无关的文件。
- 不要泄露密钥、Token、Cookie 或私有配置。

## 修改后检查

写完代码后必须检查：

- 是否真的写入了文件，而不是只在回复里贴代码。
- 是否改了无关文件。
- 是否破坏已有 API、字段名、路由或组件参数。
- 是否存在明显重复逻辑。
- 是否处理了失败状态和边界条件。
- 是否需要同步更新引用路径、导入路径或配置。
- 是否需要测试、构建、语法检查或类型检查。

## 验证要求

如果项目存在可用命令，优先执行：

```text
npm run build
npm test
npm run lint
node --check <changed-js-file>
```

验证失败时：

1. 读取错误输出。
2. 定位最可能的原因。
3. 做最小修复。
4. 再次验证。
5. 不能把失败验证说成成功。

## 最终回复要求

最终回复要简洁说明：

- 修改了什么。
- 涉及哪些文件。
- 验证是否通过。
- 如果验证失败或跳过，说明具体原因。
