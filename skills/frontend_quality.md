# 前端质量检查

这个技能用于前端页面、组件、样式和交互的质量检查。它适合和 `coding_agent` 一起使用。

## 使用时机

- 用户要求创建或修改页面、组件、样式、布局、表单、弹窗、工具栏、代码块展示等。
- 用户反馈页面错位、溢出、遮挡、空白、按钮不协调、代码块不好看。
- 修改涉及 Vue、React、HTML、CSS、图标、响应式布局或前端构建。

## 修改前要求

1. 先读取现有页面或组件，不要凭空设计。
2. 查找已有样式类、布局方式、颜色、间距和组件习惯。
3. 确认目标页面是在工作台、设置页、会话区还是独立页面。
4. 如果已有设计系统或组件库，优先沿用。

## 视觉和交互标准

- 页面要像实际可用的产品界面，不要做成纯展示稿。
- 控件大小、间距、字体层级要稳定。
- 文字不能溢出按钮、卡片、表格或代码块。
- 移动端和桌面端都不能出现明显遮挡、横向溢出或错位。
- 代码块要有清晰边界、语言标题、复制按钮位置和足够内边距。
- 工具按钮优先使用图标，陌生图标需要 tooltip 或可理解的文本。
- 不要在卡片里再套大卡片，避免页面变得笨重。
- 不要让 UI 只依赖单一色系，除非项目原本就是这种风格。

## 前端修改后检查

写完后检查：

- 组件是否能正常导入。
- 样式选择器是否影响过大。
- 深色/浅色或当前主题下是否可读。
- 长文本、空状态、加载中、错误状态是否可用。
- 表格、代码块、按钮、输入框在窄屏下是否会挤坏。
- 是否破坏已有滚动区域、固定导航、侧边栏或会话流。

## 验证要求

如果可用，优先执行：

```text
npm run build
npm run lint
```

如果有本地浏览器检查能力，应检查：

```text
桌面视口
移动端视口
页面是否空白
关键内容是否被遮挡
代码块/按钮文字是否溢出
```

验证失败时，必须先修复再结束；不能把失败构建或明显错位说成完成。

## 最终回复要求

最终回复要说明：

- 修改了哪个页面或组件。
- 主要改善了哪些视觉/交互问题。
- 构建或检查结果。
- 如果没有截图检查能力，要明确说明只做了代码级验证。
