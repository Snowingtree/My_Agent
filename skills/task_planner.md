# 任务规划 Skill

## 功能
在真正动手前把目标、步骤、依赖和风险理清，适合复杂任务的前置规划。

## 适用场景
- 用户要求制定计划、路线图或架构思路。
- 用户描述复杂功能，希望先拆解步骤。
- 任务存在依赖、风险或多个实施阶段。
- 用户问“应该怎么做”，而不是“现在直接帮我做”。

## 输入参数
- `goal`: 目标结果。
- `known_context`: 已知需求、约束和项目背景。
- `risks`: 不确定点、缺失依赖或操作风险。

## 执行流程
1. 用具体语言复述目标。
2. 把工作拆成有顺序的阶段。
3. 标出依赖、阻塞点和验证节点。
4. 保持计划可执行，不做空泛描述。
5. 如果用户之后要求开始实现，再切换到编码助手流程。

## 工具规则
- 默认不写文件。
- 只有在工作区证据能明显提升计划质量时，才使用读取、搜索或目录工具。
- 不执行破坏性操作或写入类操作。

## 安全限制
- 不要把不确定的问题说成已经确定。
- 不要过度设计简单任务。
- 除非用户明确把任务改为实施，否则不修改文件。

## 输出要求
- 输出简洁的分步骤计划。
- 对影响执行的风险和假设进行说明。
- 计划要具体到能指导下一步编码实施。
