# 前端视觉设计 Skill

## 功能
提升前端页面的视觉质量。重点关注有意图的布局、更强的排版、统一的颜色、响应式体验和有意义的交互动效。

## 适用场景
- 用户要求设计或编写网页、落地页、后台、博客页、商城页、组件或可视化界面。
- 用户觉得页面普通、拥挤、不好看、太模板化，想要更现代。
- 任务涉及 HTML、CSS、Vue、React、组件布局、响应式设计或交互细节。
- 用户希望在实现前或实现中获得设计方向。

## 输入参数
- `page_goal`: 页面目标。
- `content`: 页面要展示的文本、区块、数据或商品信息。
- `target_files`: HTML、CSS、JS、Vue、React 等前端文件。
- `style_constraints`: 品牌、氛围、颜色、间距、设备或框架要求。

## 设计流程
1. 明确目标用户和页面目的。
2. 先规划布局层级，再写代码。
3. 选择清晰的视觉方向，避免默认模板感。
4. 定义字体、颜色变量、间距、卡片、阴影和响应式行为。
5. 用户要求创建或修改页面时，必须写入真实文件。
6. 检查页面结构、样式引用和资源路径是否合理。

## 视觉规则
- 避免默认感强的页面，除非项目已有设计系统要求。
- 避免把通用 Bootstrap 蓝作为主视觉。
- 优先使用 CSS 变量管理颜色、间距、圆角和阴影。
- 字体要有表达力，但必须保持可读。
- 可以使用背景层、渐变、卡片、细微纹理或构图增强氛围。
- 动效要克制且有意义，例如入场、悬浮、激活或面板切换。
- 桌面端和移动端都要有明确布局。

## 实现规则
- 用户要求完整页面时，保存到指定文件，不要把整页代码输出到聊天框。
- CSS 过大或用户要求拆分时，将 CSS 放入独立样式文件并正确引用。
- 需要 JavaScript 行为时，保持逻辑简洁，并和可见交互对应。
- 尽量使用语义化 HTML。
- 修改已有项目时，优先遵守项目现有结构和风格。

## 可访问性规则
- 使用 `header`、`nav`、`main`、`section`、`footer` 等语义结构。
- 保持合理的标题层级。
- 交互元素需要清晰的 focus 状态。
- 文本对比度要可读。
- 按钮和输入区域要有足够点击尺寸。

## 安全限制
- 不要编造可用的后端接口。
- 不要引用明显不存在的远程资源。
- 不要在前端文件中暴露密钥。
- 未检查前不要破坏已有文件引用或导入路径。

## 输出要求
- 用户要求实现时，必须写入工作区文件。
- 简短说明设计方向。
- 说明修改了哪些文件以及验证结果。
- 除非用户明确要求，不要在最终回复中粘贴完整页面代码。
